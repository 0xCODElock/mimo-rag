# 📊 Token Usage Estimates — MiMo-RAG

This document provides a detailed breakdown of expected MiMo API token consumption for the MiMo-RAG system under various deployment scenarios.

---

## Why This System Uses a Lot of Tokens

### 1. Multi-Turn Conversation Memory

The `ConversationSession` class maintains **full conversation history** per user session. Every new message appends all previous turns to the prompt:

```
Turn 1 prompt: system (200) + context (1,500) + query (50)         = ~1,750 tokens
Turn 2 prompt: system (200) + history (1,800) + context (1,500) + query (50)  = ~3,550 tokens
Turn 3 prompt: system (200) + history (3,600) + context (1,500) + query (50)  = ~5,350 tokens
...
Turn 10 prompt: ~18,000+ tokens
```

A single 10-turn session can consume **~80,000–100,000 tokens** total.

---

### 2. Batch Document Summarization

The `BatchProcessor` sends **one full API call per document**. For a library of 500 documents averaging 5 pages each:

```
500 docs × avg 1,200 tokens/call = 600,000 tokens per batch run
```

Weekly automated re-summarization: **~2.4M tokens/month**

---

### 3. MiMo-V2.5 1M Context Window Utilization

For deep analysis tasks (e.g., legal document review, research synthesis), the system leverages MiMo-V2.5's **1 million token context window** to load entire documents without chunking:

```
1 deep analysis call = up to 800,000 input tokens + 2,000 output tokens
```

Even 10 such calls/month = **~8M tokens**.

## Token Budget Request Justification

For initial development and testing of the full production pipeline (Scenario: Medium Deployment), we estimate requiring:

> **~50,000,000 tokens/month minimum**

This covers:
- Active multi-user testing (50 concurrent test users)
- Batch pipeline stress testing with 500-document corpora
- Multi-turn session load testing (8+ turns average)
- Evaluation runs comparing MiMo-V2.5 vs MiMo-V2-Flash output quality
- Buffer for failed/retried requests (~15% overhead)
